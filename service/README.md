# NIL public collection service

The framework-independent Worker handler is `api.ts`; `migrations/0001_collector.sql` is an additive SQLite/D1 migration. This code never executes configuration text, fetches a submitted URL, probes a VPN endpoint, or accepts a remote include. All source URLs are reconstructed from the validated canonical repository's `sources.json` and fetched over verified HTTPS from `raw.githubusercontent.com`, without redirects. Limits cover time, bytes, source count, request bodies and candidate scanning.

`POST /api/sync` merges the real GitHub snapshot, permanent seen registry and history into the database under an atomic lease. It never replaces newer manual results. Run once after deployment; reads return 503 until initialized. `POST /api/collect` with `{ "limit": 50 }` fetches real sources immediately, interleaves them and commits at most 50 genuinely new records. A shared 60-second cooldown and 90-second lease serialize concurrent callers; 429 includes `Retry-After`. Zero new records is a valid result. Source failures preserve earlier records and their success timestamp. A bounded scan can defer remaining candidates; persisted cursors rotate the starting point.

`GET /api/data` returns a coherent snapshot/status/history plus a stable dataset identity and archive checkpoint. Snapshot is bounded to the latest 1,000 records and a 3 MiB record budget; the permanent registry and complete database history are retained. `GET /api/export?cursor=0&until=CHECKPOINT&limit=100` exports records under a fixed checkpoint for archival. Every SQL value is parameterized; leases prevent stale workers from committing.

`GET /api/subscription?protocol=all&source=all&q=&format=base64&title=NIL` returns a live subscription made only of actual retained URIs. Protocol may be `vless`, `vmess`, `trojan`, `ss`, `hysteria2` or `tuic`; source must match the configured manifest. `plain` is also supported. The title and two-hour update hint use standard profile headers. No traffic balance, expiry date, working connection or latency is invented.

The public API intentionally needs no secret in a public PWA. Mutating browser requests enforce the same origin (plus explicit native origins); body/query options are narrow. No wildcard CORS or credential cookies. Public users share the cooldown. Same-origin checks do not authenticate CLI callers: this is a public collection service, so infrastructure-level rate limiting should also be used if abuse demands it.

GitHub's scheduled workflow calls this same authoritative service, imports every unarchived manual/scheduled record with URI hash validation, and commits the public archive. A service outage records a failed status rather than starting a second independent registry. `collector --limit 50` remains a standalone developer command; the deployed workflow uses `collector --service --limit 50`. Never alternate standalone production collection and the service without merging state first.

The production adapter must access the platform's request-scoped D1 `DB` binding and wrap responses in the documented security headers. No database credential belongs in the frontend or repository. `scripts/package-runtime.py` packages only built static files, runtime TypeScript, migrations and SHA-256 provenance for a pinned hosted deployment. The hosting checkout and trusted platform builder own deployment; the archive contains no package installer, SDK or secrets.

Verification: `npm run test:service` exercises real SQLite leases/transactions, parser equivalence against Python, all committed URI IDs, source restrictions, malicious requests, subscription contents, failures and export pagination. Browser tests simulate API responses; production verification must additionally call the actual deployed endpoints and parse their returned URIs. An HTTP 200 from one location does not prove reachability on every Iranian network.
